## 1. Search Insert Position

**Difficulty:** Easy
**Link:** https://leetcode.com/problems/search-insert-position/

### Problem

Given a sorted array of distinct integers and a target value, return the index if the target is found. If not, return the index where it would be inserted to keep the array sorted. Must run in O(log n).

**Examples**
- `nums = [1,3,5,6], target = 5` → `2`
- `nums = [1,3,5,6], target = 2` → `1`
- `nums = [1,3,5,6], target = 7` → `4`

**Constraints:** `1 <= nums.length <= 10^4`, values in `[-10^4, 10^4]`, `nums` sorted ascending and distinct.

### Intuition

The array is sorted, and we need O(log n) — that's the classic signal for binary search. The trick that makes this problem barely different from "find the index of target" is: **binary search naturally converges on the insertion point even when the target isn't present.** If you binary search with the invariant "everything left of `lo` is `< target`, everything at or right of `lo` is `>= target`", then when the loop ends, `lo` is exactly the answer — whether or not `target` was actually found.

### Step-by-step walkthrough

1. Set `lo = 0`, `hi = len(nums) - 1`.
2. While `lo <= hi`:
   - Compute `mid = (lo + hi) // 2`.
   - If `nums[mid] == target`, we found it — return `mid` immediately.
   - If `nums[mid] < target`, the target (or its insertion spot) must be to the right, so `lo = mid + 1`.
   - Else (`nums[mid] > target`), move left: `hi = mid - 1`.
3. When the loop exits, `lo` has crossed past `hi` such that `lo` is the first index whose value is `>= target` — exactly where `target` should be inserted.
4. Return `lo`.

Trace with `nums = [1,3,5,6], target = 2`:
- `lo=0, hi=3, mid=1` → `nums[1]=3 > 2` → `hi=0`
- `lo=0, hi=0, mid=0` → `nums[0]=1 < 2` → `lo=1`
- `lo=1 > hi=0`, loop ends → return `1`. Correct: inserting 2 between 1 and 3 gives index 1.

### Complexity

- **Time:** O(log n) — standard binary search halves the search space each step.
- **Space:** O(1) — only a few integer pointers.

### Python Solution

```python
class Solution:
    def searchInsert(self, nums: list[int], target: int) -> int:
        lo, hi = 0, len(nums) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if nums[mid] == target:
                return mid
            elif nums[mid] < target:
                lo = mid + 1
            else:
                hi = mid - 1
        return lo


if __name__ == "__main__":
    sol = Solution()
    print(sol.searchInsert([1, 3, 5, 6], 5))  # 2
    print(sol.searchInsert([1, 3, 5, 6], 2))  # 1
    print(sol.searchInsert([1, 3, 5, 6], 7))  # 4
```

## 2. Repeated String Match

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/repeated-string-match/

### Problem

Given strings `a` and `b`, return the minimum number of times you must repeat `a` so that `b` becomes a substring of the repeated string. Return `-1` if impossible.

**Examples**
- `a = "abcd", b = "cdabcdab"` → `3` (`"abcdabcdabcd"` contains `b`)
- `a = "a", b = "aa"` → `2`

**Constraints:** `1 <= a.length, b.length <= 10^4`, lowercase letters only.

### Intuition

First, figure out a *lower bound* on how many repeats you could possibly need: to even have a chance of `b` fitting inside repeated `a`, the repeated string's length must be at least `len(b)`. That gives `min_repeats = ceil(len(b) / len(a))`.

But that might not be enough — `b` could straddle the boundary between the last copy and one more copy of `a` (imagine `b` starts near the end of one repetition and finishes in the next). So the real trick is: **try `min_repeats` copies, and if that doesn't contain `b`, try one extra copy (`min_repeats + 1`).** One extra copy is always suffient to cover any boundary-straddling case, because `b`'s length is at most `len(a) * min_repeats`, so adding one more full copy of `a` (length `len(a)`) guarantees enough "runway" past any starting offset within the first copy. If it's still not found after that, it's genuinely impossible — return -1.

### Step-by-step walkthrough

1. Compute `min_repeats = ceil(len(b) / len(a))` using integer math: `(len(b) + len(a) - 1) // len(a)`.
2. Build `candidate = a * min_repeats`. If `b in candidate`, return `min_repeats`.
3. Otherwise, try one more copy: `candidate += a` (now `min_repeats + 1` copies). If `b in candidate`, return `min_repeats + 1`.
4. If neither works, return `-1` (this correctly handles cases where `b` contains a character not in `a` at all, since Python's `in` check will simply never match).

Trace `a = "abcd", b = "cdabcdab"` (len(a)=4, len(b)=8):
- `min_repeats = ceil(8/4) = 2` → `"abcdabcd"` — does it contain `"cdabcdab"`? No (length matches exactly but the alignment doesn't).
- Try 3 copies: `"abcdabcdabcd"` — contains `"cdabcdab"` starting at index 2. Return `3`. ✓

### Complexity

- **Time:** O(n · (n + m)) worst case, where `n = len(a)`, `m = len(b)` — building the candidate string is O(n · min_repeats) ≈ O(m + n), and Python's substring search (`in`) uses an efficient algorithm close to O(len(candidate) + len(b)). Overall this is efficient in practice, roughly O(n + m).
- **Space:** O(n + m) for the candidate string.

### Python Solution

```python
class Solution:
    def repeatedStringMatch(self, a: str, b: str) -> int:
        min_repeats = -(-len(b) // len(a))  # ceil division
        candidate = a * min_repeats
        if b in candidate:
            return min_repeats
        candidate += a
        if b in candidate:
            return min_repeats + 1
        return -1


if __name__ == "__main__":
    sol = Solution()
    print(sol.repeatedStringMatch("abcd", "cdabcdab"))  # 3
    print(sol.repeatedStringMatch("a", "aa"))            # 2
```

## 3. Statistics from a Large Sample

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/statistics-from-a-large-sample/

### Problem

You're given `count`, an array of length 256 where `count[k]` is how many times the value `k` appears in a large sample. Return `[minimum, maximum, mean, median, mode]` as floats.

**Constraints:** `count.length == 256`, `0 <= count[i] <= 10^9`, `1 <= sum(count) <= 10^9`, mode is unique.

### Intuition

The sample can be huge (up to 10^9 elements), so you can never materialize it — everything has to be derived directly from the `count` array using running totals.

- **Minimum/maximum:** the smallest/largest index `k` with `count[k] > 0`.
- **Mode:** the index `k` with the largest `count[k]`.
- **Mean:** `sum(k * count[k]) / sum(count[k])`.
- **Median:** the hard part per the hint. With total size `n = sum(count)`, if `n` is odd you need the single middle element (rank `(n+1)//2`); if even, you need the average of ranks `n//2` and `n//2 + 1`. Walk through indices `0..255` accumulating a running total of how many elements you've "seen so far"; the first index where the running total reaches or passes a target rank is the value at that rank.

### Step-by-step walkthrough

1. Compute `n = sum(count)`.
2. Scan `k` from 0 to 255 to find `minimum` (first `k` with `count[k] > 0`) and `maximum` (last such `k`).
3. Compute `total = sum(k * count[k] for k in range(256))`, then `mean = total / n`.
4. Find `mode = argmax(count)`.
5. For the median: determine target rank(s) — `[(n+1)//2]` if `n` is odd, or `[n//2, n//2+1]` if even (1-indexed ranks). Walk `k` from 0 to 255 keeping a running cumulative count; whenever the cumulative count first reaches or exceeds a needed rank, that `k` is the value at that rank. Average the one or two values found.
6. Return `[minimum, maximum, mean, median, mode]` as floats.

Trace with `count` representing sample `[1,2,2,2,3,3,3,3]` (n=8, even):
- min=1, max=3, mean=19/8=2.375, mode=3 (appears 4 times).
- Need ranks 4 and 5 (0..255 walk): cumulative after k=1 is 1, after k=2 is 1+3=4 (rank 4 found → value 2), after k=3 is 4+4=8 (rank 5 found → value 3). Median = (2+3)/2 = 2.5. Matches expected output.

### Complexity

- **Time:** O(256) = O(1) — the range of possible values is fixed regardless of how large the sample is.
- **Space:** O(1) extra (excluding the input array).

### Python Solution

```python
class Solution:
    def sampleStats(self, count: list[int]) -> list[float]:
        n = sum(count)

        minimum = next(k for k in range(256) if count[k] > 0)
        maximum = next(k for k in range(255, -1, -1) if count[k] > 0)

        total = sum(k * c for k, c in enumerate(count))
        mean = total / n

        mode = max(range(256), key=lambda k: count[k])

        if n % 2 == 1:
            target_ranks = [(n + 1) // 2]
        else:
            target_ranks = [n // 2, n // 2 + 1]

        median_values = []
        cumulative = 0
        rank_idx = 0
        for k in range(256):
            cumulative += count[k]
            while rank_idx < len(target_ranks) and cumulative >= target_ranks[rank_idx]:
                median_values.append(k)
                rank_idx += 1
            if rank_idx == len(target_ranks):
                break
        median = sum(median_values) / len(median_values)

        return [float(minimum), float(maximum), mean, median, float(mode)]


if __name__ == "__main__":
    sol = Solution()
    count1 = [0] * 256
    for v, c in {1: 1, 2: 2, 3: 4}.items():
        count1[v] = c
    print(sol.sampleStats(count1))  # [1.0, 3.0, 2.375, 2.5, 3.0]
```

## 4. Slowest Key

**Difficulty:** Easy
**Link:** https://leetcode.com/problems/slowest-key/

### Problem

A sequence of `n` keys was pressed. `keysPressed[i]` is the key, `releaseTimes[i]` is when it was released (sorted, non-decreasing). Key 0 was pressed at time 0; every next key was pressed the instant the previous one was released. Duration of press `i` is `releaseTimes[i] - releaseTimes[i-1]` (or just `releaseTimes[0]` for `i=0`). Return the key with the longest duration; break ties by lexicographically largest key.

**Examples**
- `releaseTimes = [9,29,49,50], keysPressed = "cbcd"` → `"c"`
- `releaseTimes = [12,23,36,46,62], keysPressed = "spuda"` → `"a"`

**Constraints:** `2 <= n <= 1000`, `1 <= releaseTimes[i] <= 10^9`, strictly increasing release times, lowercase letters.

### Intuition

This is a straightforward single-pass scan. Each keypress's duration is just the gap between consecutive release times (with the first duration being `releaseTimes[0] - 0`). Track the best `(duration, key)` seen so far, updating whenever we find a strictly longer duration, or a tie with a lexicographically larger key.

### Step-by-step walkthrough

1. Initialize `best_duration = releaseTimes[0]`, `best_key = keysPressed[0]`.
2. For `i` from 1 to `n-1`:
   - `duration = releaseTimes[i] - releaseTimes[i-1]`.
   - If `duration > best_duration`, or (`duration == best_duration` and `keysPressed[i] > best_key`), update `best_duration = duration`, `best_key = keysPressed[i]`.
3. Return `best_key`.

Trace `releaseTimes = [9,29,49,50], keysPressed = "cbcd"`:
- Start: best = (9, 'c').
- i=1: duration=20 ('b') > 9 → best=(20,'b').
- i=2: duration=20 ('c'), tie with 20, but 'c' > 'b' → best=(20,'c').
- i=3: duration=1 ('d') < 20 → no change.
- Return `'c'`. ✓

### Complexity

- **Time:** O(n) — single linear scan.
- **Space:** O(1) extra.

### Python Solution

```python
class Solution:
    def slowestKey(self, releaseTimes: list[int], keysPressed: str) -> str:
        best_duration = releaseTimes[0]
        best_key = keysPressed[0]

        for i in range(1, len(releaseTimes)):
            duration = releaseTimes[i] - releaseTimes[i - 1]
            key = keysPressed[i]
            if duration > best_duration or (duration == best_duration and key > best_key):
                best_duration = duration
                best_key = key

        return best_key


if __name__ == "__main__":
    sol = Solution()
    print(sol.slowestKey([9, 29, 49, 50], "cbcd"))          # "c"
    print(sol.slowestKey([12, 23, 36, 46, 62], "spuda"))    # "a"
```

## 5. Maximum Alternating Subsequence Sum

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/maximum-alternating-subsequence-sum/

### Problem

The alternating sum of a 0-indexed array is `sum(elements at even indices) - sum(elements at odd indices)`. Given `nums`, find the maximum alternating sum achievable by any subsequence (after reindexing the chosen elements from 0).

**Examples**
- `nums = [4,2,5,3]` → `7` (pick `[4,2,5]`: `(4+5) - 2 = 7`)
- `nums = [5,6,7,8]` → `8` (pick `[8]`)
- `nums = [6,2,1,2,4,5]` → `10` (pick `[6,1,5]`: `(6+5) - 1 = 10`)

**Constraints:** `1 <= nums.length <= 10^5`, `1 <= nums[i] <= 10^5`.

### Intuition

This is a classic DP-with-two-states problem, exactly as the hints suggest. As we scan left to right deciding what to include, we only need to track two running best values:

- `even`: the best alternating sum achievable using a prefix of `nums`, where the subsequence chosen so far has an **even** number of elements (possibly zero) — meaning we're "ready" for the next taken element to land in a positive (even-index) slot.
- `odd`: the best alternating sum so far where the subsequence chosen has an **odd** number of elements — ready for the next taken element to land in a negative (odd-index) slot.

Both start at `0`: an empty subsequence has sum 0 and counts as "even" (zero elements), and starting `odd` at 0 too is valid because you're always allowed to *begin* your subsequence with any element as its first (positive) pick — so "odd count with sum 0" is reachable by simply not having committed to anything negative yet.

Transition for each new number `x`:
- `new_even = max(even, odd + x)` — either skip `x` (stay even), or add `x` as a positive term, moving from odd count to even count.
- `new_odd = max(odd, even - x)` — either skip `x` (stay odd), or add `x` as a negative term, moving from even count to odd count.

Both updates use the *old* values of `even` and `odd` (computed before either is overwritten), then are applied simultaneously. This is the same rolling-optimum trick used in "Best Time to Buy and Sell Stock II" — greedily banking every profitable local rise.

### Step-by-step walkthrough

1. Initialize `even = 0`, `odd = 0`.
2. For each `x` in `nums`, simultaneously update:
   - `new_even = max(even, odd + x)`
   - `new_odd = max(odd, even - x)`
3. Answer is `even` at the end (an optimal subsequence never benefits from ending on a dangling negative term, so the best full result is always captured in the even-count state).

Trace `nums = [4,2,5,3]`:
- Start: even=0, odd=0.
- x=4: new_even=max(0,0+4)=4; new_odd=max(0,0-4)=0. → even=4, odd=0.
- x=2: new_even=max(4,0+2)=4; new_odd=max(0,4-2)=2. → even=4, odd=2.
- x=5: new_even=max(4,2+5)=7; new_odd=max(2,4-5)=2. → even=7, odd=2.
- x=3: new_even=max(7,2+3)=7; new_odd=max(2,7-3)=4. → even=7, odd=4.
- Final `even = 7`. ✓ Matches expected output.

Trace `nums=[5,6,7,8]`: even=0,odd=0 → x=5: even=5,odd=0 → x=6: even=max(5,0+6)=6,odd=max(0,5-6)=0 → x=7: even=max(6,7)=7,odd=max(0,6-7)=0 → x=8: even=max(7,8)=8,odd=max(0,7-8)=0. Final even=8. ✓

### Complexity

- **Time:** O(n) — one linear pass with O(1) work per element.
- **Space:** O(1) extra.

### Python Solution

```python
class Solution:
    def maxAlternatingSum(self, nums: list[int]) -> int:
        even, odd = 0, 0
        for x in nums:
            even, odd = max(even, odd + x), max(odd, even - x)
        return even


if __name__ == "__main__":
    sol = Solution()
    print(sol.maxAlternatingSum([4, 2, 5, 3]))     # 7
    print(sol.maxAlternatingSum([5, 6, 7, 8]))     # 8
    print(sol.maxAlternatingSum([6, 2, 1, 2, 4, 5]))  # 10
```

## 6. Lexicographically Smallest String After Applying Operations

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/lexicographically-smallest-string-after-applying-operations/

### Problem

Given a digit string `s` of even length and integers `a`, `b`, you may repeatedly apply either operation, in any order, any number of times:
1. **Add:** add `a` to every digit at an odd index, mod 10 (wraps 9→0 etc., since these are single digits 0-9).
2. **Rotate:** rotate the string right by `b` positions.

Return the lexicographically smallest string obtainable.

**Examples**
- `s="5525", a=9, b=2` → `"2050"`
- `s="74", a=5, b=1` → `"24"`
- `s="0011", a=4, b=2` → `"0011"` (no improvement possible)

**Constraints:** `2 <= s.length <= 100` (even), `1 <= a <= 9`, `1 <= b <= s.length - 1`.

### Intuition

The hints spell this out directly: since `s.length <= 100`, and each digit can only take one of 10 values under repeated "add `a` mod 10" (there are at most 10 distinct "add" states reachable per starting digit before it cycles back), and rotation has at most `s.length` distinct positions, the total reachable state space is bounded by roughly `10 * s.length` (at most 1000) — small enough for a brute-force BFS/DFS over all reachable strings, taking the lexicographic minimum of everything visited.

This is a graph-reachability problem: treat each distinct string as a node, with edges being "apply rotate" or "apply add." Starting from `s`, explore everything reachable via BFS, tracking visited strings to avoid cycles, and return the minimum string seen.

### Step-by-step walkthrough

1. Maintain a `visited` set (starts containing just `s`) and a queue/stack initialized with `s`.
2. While the frontier isn't empty, pop a string `cur`:
   - **Add:** build `added` by adding `a` to every digit at an odd index (mod 10), leaving even-index digits unchanged. If `added` not in `visited`, add it to `visited` and the frontier.
   - **Rotate:** build `rotated = cur[-b:] + cur[:-b]` (rotate right by `b`). If `rotated` not in `visited`, add it to `visited` and the frontier.
3. After exploring everything reachable, return `min(visited)` (Python string comparison is exactly lexicographic for equal-length digit strings).

Trace `s="74", a=5, b=1` (length 2, so rotate by 1 swaps the two characters):
- Start: visited={"74"}.
- From "74": add → digit at odd index 1 is '4', +5 mod 10 = 9 → "79"; rotate right by 1 → "47".
- From "79": add → "74" (revisits, +5 twice cycles back after 2 steps since 5*2=10≡0); rotate → "97".
- From "47": add → odd index digit '7'+5=12 mod10=2 → "42"; rotate → "74" (revisit).
- From "97": add → "92"; rotate → "79" (revisit).
- From "42": add → "47" (revisit, since 2+5=7); rotate → "24".
- From "92": add → "97" (revisit); rotate → "29".
- From "24": add → "29"; rotate → "42" (revisit).
- From "29": add → "24" (revisit); rotate → "92" (revisit).
- Full visited set: {"74","79","47","97","42","92","24","29"}. Minimum is `"24"`. ✓ Matches expected.

### Complexity

- **Time:** O(V · L) where `V` is the number of distinct reachable strings (bounded by roughly `10 * L`, since the digit pattern has at most `10` "phases" under repeated adds combined with at most `L` rotation offsets) and `L = len(s)` is the cost of building each new string. With `L <= 100`, this is comfortably fast — at most a few thousand string operations.
- **Space:** O(V · L) to store all visited strings.

### Python Solution

```python
class Solution:
    def findLexSmallestString(self, s: str, a: int, b: int) -> str:
        n = len(s)
        visited = {s}
        stack = [s]

        while stack:
            cur = stack.pop()

            # Operation 1: add `a` to every odd-indexed digit, mod 10.
            added_chars = list(cur)
            for i in range(1, n, 2):
                added_chars[i] = str((int(added_chars[i]) + a) % 10)
            added = "".join(added_chars)
            if added not in visited:
                visited.add(added)
                stack.append(added)

            # Operation 2: rotate right by b.
            rotated = cur[-b:] + cur[:-b]
            if rotated not in visited:
                visited.add(rotated)
                stack.append(rotated)

        return min(visited)


if __name__ == "__main__":
    sol = Solution()
    print(sol.findLexSmallestString("5525", 9, 2))  # "2050"
    print(sol.findLexSmallestString("74", 5, 1))     # "24"
    print(sol.findLexSmallestString("0011", 4, 2))   # "0011"
```

## 7. Maximum Value of an Ordered Triplet I

**Difficulty:** Easy
**Link:** https://leetcode.com/problems/maximum-value-of-an-ordered-triplet-i/

### Problem

Given `nums`, find the maximum value of `(nums[i] - nums[j]) * nums[k])` over all triplets of indices `i < j < k`. If every triplet's value is negative, return `0`.

**Examples**
- `nums = [12,6,1,2,7]` → `77` (triplet `(0,2,4)`: `(12-1)*7=77`)
- `nums = [1,10,3,4,19]` → `133` (triplet `(1,2,4)`: `(10-3)*19=133`)
- `nums = [1,2,3]` → `0` (only triplet gives `-3`, clamp to 0)

**Constraints:** `3 <= nums.length <= 100`, `1 <= nums[i] <= 10^6`.

The hint suggests brute force with three nested loops, which is entirely fine given `n <= 100` (at most ~161,700 triplets) — but it's worth knowing the O(n) one-pass trick too, since it generalizes to the "Ordered Triplet II" follow-up where `n` can be much larger.

### Intuition (O(n) approach)

To maximize `(nums[i] - nums[j]) * nums[k]` with `i < j < k`, scan `k` from left to right while maintaining, for everything strictly before the current `j`-candidate:
- `max_i_so_far`: the largest `nums[i]` seen for indices before the current position (candidate for the "i" role).
- `max_diff_so_far`: the largest value of `(nums[i] - nums[j])` achievable using the best `i` before each `j` seen so far (candidate "i minus j" pair).

As we move a single pointer `m` through the array standing in for "j," at each step:
1. Before treating `nums[m]` as `k`, update the running best answer using `max_diff_so_far * nums[m]` (treating `m` as `k`, using the best `(i,j)` diff found using indices strictly before `m`).
2. Then update `max_diff_so_far = max(max_diff_so_far, max_i_so_far - nums[m])` (treating `nums[m]` as a candidate `j` for future `k`s, paired with the best `i` before it).
3. Then update `max_i_so_far = max(max_i_so_far, nums[m])` (treating `nums[m]` as a candidate `i` for future `j`s).

This single pass correctly keeps `i < j < k` since each quantity only incorporates indices strictly before the current one, updated in the right order (use diff before updating diff, use i before updating i).

### Step-by-step walkthrough

1. Initialize `best = 0`, `max_i = 0`, `max_diff = 0` (using 0 as a safe floor since all `nums[i] >= 1`, so `max_i` starts effectively "unset").
2. For each `x` in `nums` (in order, playing the role of "current index," potentially `k`):
   - `best = max(best, max_diff * x)` — try `x` as `k`.
   - `max_diff = max(max_diff, max_i - x)` — try `x` as `j`, paired with the best `i` seen so far.
   - `max_i = max(max_i, x)` — try `x` as `i` for future iterations.
3. Return `best`.

Trace `nums = [12,6,1,2,7]`:
- x=12: best=max(0,0*12)=0; max_diff=max(0,0-12)=0 (since max_i=0 initially, floor prevents negative); max_i=max(0,12)=12.
- x=6: best=max(0,0*6)=0; max_diff=max(0,12-6)=6; max_i=max(12,6)=12.
- x=1: best=max(0,6*1)=6; max_diff=max(6,12-1)=11; max_i=max(12,1)=12.
- x=2: best=max(6,11*2)=22; max_diff=max(11,12-2)=11; max_i=max(12,2)=12.
- x=7: best=max(22,11*7)=77; max_diff=max(11,12-7)=11; max_i=max(12,7)=12.
- Final best = 77. ✓

### Complexity

- **Time:** O(n) — single pass, O(1) work per element. (The brute-force triple-loop alternative is O(n^3), which is also fine at `n <= 100` but doesn't scale.)
- **Space:** O(1) extra.

### Python Solution

```python
class Solution:
    def maximumTripletValue(self, nums: list[int]) -> int:
        best = 0
        max_i = 0
        max_diff = 0

        for x in nums:
            best = max(best, max_diff * x)
            max_diff = max(max_diff, max_i - x)
            max_i = max(max_i, x)

        return best


if __name__ == "__main__":
    sol = Solution()
    print(sol.maximumTripletValue([12, 6, 1, 2, 7]))   # 77
    print(sol.maximumTripletValue([1, 10, 3, 4, 19]))  # 133
    print(sol.maximumTripletValue([1, 2, 3]))          # 0
```
