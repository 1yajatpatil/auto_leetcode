## 1. Verify Preorder Serialization of a Binary Tree

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/verify-preorder-serialization-of-a-binary-tree/

### Problem

A binary tree can be serialized via preorder traversal, writing each node's value and using `'#'` for null children. For example, `"9,3,4,#,#,1,#,#,2,#,6,#,#"`. Given a comma-separated `preorder` string (guaranteed to contain only integers or `'#'`), determine whether it is a valid preorder serialization — **without reconstructing the tree**.

**Examples**
- `preorder = "9,3,4,#,#,1,#,#,2,#,6,#,#"` → `true`
- `preorder = "1,#"` → `false`
- `preorder = "9,#,#,1"` → `false`

**Constraints:** `1 <= preorder.length <= 10^4`; values are integers in `[0, 100]` or `'#'`, comma-separated.

### Intuition

Reconstructing the tree is overkill. Instead, think in terms of **available "slots"**: every node (real or null) consumes one slot from its parent, and every non-null node opens up two new slots for its children. Start with 1 available slot (for the root). As you scan tokens left to right, each token consumes one slot; if a token is a real number, it also produces two new slots. The serialization is valid exactly when:
1. You never run out of slots mid-scan (you can't consume a slot that doesn't exist), and
2. You end with exactly 0 slots remaining after consuming every token.

This is equivalent to tracking node/null "degree" as a running counter, a classic trick that avoids building any tree structure at all.

### Step-by-step walkthrough

1. Initialize `slots = 1` (the root needs one slot to be placed into).
2. Split `preorder` on commas to get tokens.
3. For each token:
   - If `slots <= 0`, the string is already invalid (we tried to consume a slot that isn't there) — return `False` immediately.
   - Consume one slot: `slots -= 1`.
   - If the token is **not** `'#'` (i.e., it's a real node), it introduces two children slots: `slots += 2`.
4. After processing all tokens, return `slots == 0`.

Trace with `"9,3,4,#,#,1,#,#,2,#,6,#,#"`:
- Start `slots = 1`.
- `9` (real): slots 1→0→2
- `3` (real): slots 2→1→3
- `4` (real): slots 3→2→4
- `#`: slots 4→3
- `#`: slots 3→2
- `1` (real): slots 2→1→3
- `#`: slots 3→2
- `#`: slots 2→1
- `2` (real): slots 1→0→2
- `#`: slots 2→1
- `6` (real): slots 1→0→2
- `#`: slots 2→1
- `#`: slots 1→0
- End: `slots == 0` → `True`. ✓

Trace with `"1,#"`: start `slots=1`; `1` real → slots 1→0→2; `#` → slots 2→1; end `slots=1 != 0` → `False`. ✓

### Complexity

- **Time:** O(n) — one pass over the tokens.
- **Space:** O(n) for the split token list (O(1) extra if you parse without materializing the full list, e.g. with `str.split` reused or manual index scanning).

### Python Solution

```python
class Solution:
    def isValidSerialization(self, preorder: str) -> bool:
        tokens = preorder.split(',')
        slots = 1
        for token in tokens:
            if slots <= 0:
                return False
            slots -= 1
            if token != '#':
                slots += 2
        return slots == 0


if __name__ == "__main__":
    sol = Solution()
    print(sol.isValidSerialization("9,3,4,#,#,1,#,#,2,#,6,#,#"))  # True
    print(sol.isValidSerialization("1,#"))                        # False
    print(sol.isValidSerialization("9,#,#,1"))                    # False
```

## 2. Single Number III

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/single-number-iii/

### Problem

Given an integer array `nums` where exactly two elements appear once and every other element appears exactly twice, find the two singly-occurring elements. You must run in **linear time** and use **only constant extra space** (answer may be returned in any order).

**Examples**
- `nums = [1,2,1,3,2,5]` → `[3,5]`
- `nums = [-1,0]` → `[-1,0]`
- `nums = [0,1]` → `[1,0]`

**Constraints:** `2 <= nums.length <= 3*10^4`; values fit in 32-bit signed range; exactly two integers appear once, the rest appear twice.

### Intuition

This builds directly on the classic "Single Number" XOR trick. XOR-ing every element cancels out all the duplicated numbers (since `x ^ x = 0`), leaving `xor_all = a ^ b` where `a` and `b` are the two unique numbers. The challenge is splitting `a` and `b` apart using only that combined XOR.

Key idea: since `a != b`, `xor_all` must have at least one set bit — some bit where `a` and `b` differ. Pick **any** such bit (the lowest set bit is easiest via `xor_all & -xor_all`, using two's complement). Partition all numbers into two groups based on whether that bit is set. Because `a` and `b` differ on that bit, they land in different groups. Every duplicated pair, on the other hand, has *identical* values, so both copies always land in the *same* group — they still cancel via XOR within their group. XOR-ing each group independently isolates `a` in one group and `b` in the other.

### Step-by-step walkthrough

1. Compute `xor_all` = XOR of every number in `nums`. This equals `a ^ b`.
2. Isolate the lowest set bit: `diff_bit = xor_all & (-xor_all)`.
3. Initialize `a = 0`.
4. For each number `num` in `nums`: if `num & diff_bit` is nonzero, XOR it into `a`; this partitions the array and accumulates one of the two unique numbers into `a`.
5. Compute `b = xor_all ^ a` (since `a ^ b = xor_all`, and duplicates in the "other" group all cancel out, this recovers the second unique number cleanly).
6. Return `[a, b]`.

Trace with `nums = [1,2,1,3,2,5]`:
- `xor_all = 1^2^1^3^2^5 = 3^5 = 6` (binary `110`).
- `diff_bit = 6 & -6 = 2` (binary `010`).
- Group by bit `010` set: `2` (bit set), `2` (bit set), `3`(bit set, `011`)... let's check each: `1`(`001`, bit0 unset), `2`(`010`, set), `1`(unset), `3`(`011`, set), `2`(set), `5`(`101`, unset).
- `a` accumulates XOR of set-group: `2 ^ 2 ^ 3 = 3`.
- `b = xor_all ^ a = 6 ^ 3 = 5`.
- Result `[3, 5]`. ✓ Matches expected output.

### Complexity

- **Time:** O(n) — two linear passes over `nums`.
- **Space:** O(1) — only a few integer accumulators.

### Python Solution

```python
from typing import List


class Solution:
    def singleNumber(self, nums: List[int]) -> List[int]:
        xor_all = 0
        for num in nums:
            xor_all ^= num

        diff_bit = xor_all & (-xor_all)

        a = 0
        for num in nums:
            if num & diff_bit:
                a ^= num
        b = xor_all ^ a

        return [a, b]


if __name__ == "__main__":
    sol = Solution()
    print(sol.singleNumber([1, 2, 1, 3, 2, 5]))  # [3, 5] (order may vary)
    print(sol.singleNumber([-1, 0]))             # [-1, 0]
    print(sol.singleNumber([0, 1]))              # [1, 0]
```

## 3. Concatenation of Array

**Difficulty:** Easy
**Link:** https://leetcode.com/problems/concatenation-of-array/

### Problem

Given an integer array `nums` of length `n`, build an array `ans` of length `2n` such that `ans[i] == nums[i]` and `ans[i + n] == nums[i]` for `0 <= i < n`. In other words, `ans` is `nums` concatenated with itself.

**Examples**
- `nums = [1,2,1]` → `[1,2,1,1,2,1]`
- `nums = [1,3,2,1]` → `[1,3,2,1,1,3,2,1]`

**Constraints:** `n == nums.length`, `1 <= n <= 1000`, `1 <= nums[i] <= 1000`.

### Intuition

The problem statement literally describes list concatenation: `ans` is just two copies of `nums` back to back. There's no trick here — Python's list multiplication or concatenation operator does exactly this in one line.

### Step-by-step walkthrough

1. Take the input list `nums`.
2. Concatenate it with itself: `nums + nums` (or equivalently `nums * 2`).
3. Return the result.

Trace with `nums = [1,2,1]`:
- `nums + nums = [1,2,1] + [1,2,1] = [1,2,1,1,2,1]`. ✓ Matches expected output.

### Complexity

- **Time:** O(n) — copying `n` elements twice.
- **Space:** O(n) for the output array (required by the problem; not counting the output, O(1) extra).

### Python Solution

```python
from typing import List


class Solution:
    def getConcatenation(self, nums: List[int]) -> List[int]:
        return nums + nums


if __name__ == "__main__":
    sol = Solution()
    print(sol.getConcatenation([1, 2, 1]))     # [1, 2, 1, 1, 2, 1]
    print(sol.getConcatenation([1, 3, 2, 1]))  # [1, 3, 2, 1, 1, 3, 2, 1]
```

## 4. Occurrences After Bigram

**Difficulty:** Easy
**Link:** https://leetcode.com/problems/occurrences-after-bigram/

### Problem

Given strings `text`, `first`, and `second`, find every occurrence in `text` of the pattern `"first second third"` (three consecutive space-separated words where `second` immediately follows `first`), and return the list of all matching `third` words, in order.

**Examples**
- `text = "alice is a good girl she is a good student", first = "a", second = "good"` → `["girl","student"]`
- `text = "we will we will rock you", first = "we", second = "will"` → `["we","rock"]`

**Constraints:** `1 <= text.length <= 1000`; lowercase letters and single spaces; `1 <= first.length, second.length <= 10`.

### Intuition

Split `text` into a list of words, then slide a window of three consecutive words across it. Whenever the first two words of the window match `first` and `second`, the third word is a match — collect it. This is a simple linear scan over word triples; no need for any string-searching algorithm since we're matching whole words, not substrings.

### Step-by-step walkthrough

1. Split `text` on spaces into a list `words`.
2. Initialize an empty result list.
3. Iterate `i` from `0` to `len(words) - 3` (inclusive), so that `words[i]`, `words[i+1]`, `words[i+2]` are all valid indices.
4. At each `i`, if `words[i] == first` and `words[i+1] == second`, append `words[i+2]` to the result.
5. Return the result list.

Trace with `text = "we will we will rock you"`, `first="we"`, `second="will"`:
- `words = ["we","will","we","will","rock","you"]`.
- i=0: `words[0]="we"`, `words[1]="will"` → match! append `words[2]="we"`.
- i=1: `words[1]="will"` != "we" → skip.
- i=2: `words[2]="we"`, `words[3]="will"` → match! append `words[4]="rock"`.
- i=3: `words[3]="will"` != "we" → skip.
- Result: `["we","rock"]`. ✓ Matches expected output.

### Complexity

- **Time:** O(m) where `m` is the number of words in `text` (splitting is O(len(text)), the scan is O(m)).
- **Space:** O(m) for the words list plus the output.

### Python Solution

```python
from typing import List


class Solution:
    def findOcurrences(self, text: str, first: str, second: str) -> List[str]:
        words = text.split(' ')
        result = []
        for i in range(len(words) - 2):
            if words[i] == first and words[i + 1] == second:
                result.append(words[i + 2])
        return result


if __name__ == "__main__":
    sol = Solution()
    print(sol.findOcurrences("alice is a good girl she is a good student", "a", "good"))  # ['girl', 'student']
    print(sol.findOcurrences("we will we will rock you", "we", "will"))                    # ['we', 'rock']
```

## 5. Minimum Size Subarray Sum

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/minimum-size-subarray-sum/

### Problem

Given an array of **positive** integers `nums` and a positive integer `target`, return the minimal length of a contiguous subarray whose sum is `>= target`. If no such subarray exists, return `0`.

**Examples**
- `target = 7, nums = [2,3,1,2,4,3]` → `2` (subarray `[4,3]`)
- `target = 4, nums = [1,4,4]` → `1`
- `target = 11, nums = [1,1,1,1,1,1,1,1]` → `0`

**Constraints:** `1 <= target <= 10^9`, `1 <= nums.length <= 10^5`, `1 <= nums[i] <= 10^4`.

### Intuition

Because every element is **positive**, the running sum of a window only grows as the window expands and only shrinks as it contracts — there's no way a larger window could have a smaller sum than the same window with extra elements removed. This monotonicity is exactly what makes a **sliding window (two pointers)** approach correct: grow the window by moving the right pointer to accumulate sum; once the window sum meets or exceeds `target`, shrink from the left as much as possible while still satisfying the condition, recording the minimum length seen. Since each pointer only moves forward and never backtracks, the whole scan is linear.

### Step-by-step walkthrough

1. Initialize `left = 0`, `window_sum = 0`, `min_len = infinity`.
2. Iterate `right` from `0` to `len(nums)-1`:
   - Add `nums[right]` to `window_sum`.
   - While `window_sum >= target`:
     - Update `min_len = min(min_len, right - left + 1)`.
     - Subtract `nums[left]` from `window_sum` and increment `left` (shrink from the left).
3. After the loop, return `min_len` if it was updated, else `0`.

Trace with `target=7, nums=[2,3,1,2,4,3]`:
- right=0: sum=2 (< 7)
- right=1: sum=5 (< 7)
- right=2: sum=6 (< 7)
- right=3: sum=8 (>= 7) → min_len=4 (window [0..3]); shrink: sum=8-2=6, left=1 → loop ends (6<7)
- right=4: sum=6+4=10 (>=7) → min_len=min(4, 4-1+1=4)=4; shrink: sum=10-3=7,left=2 → still >=7 → min_len=min(4,3)=3; shrink: sum=7-1=6,left=3 → loop ends
- right=5: sum=6+3=9 (>=7) → min_len=min(3,5-3+1=3)=3; shrink: sum=9-2=7,left=4 → still>=7→min_len=min(3,2)=2; shrink: sum=7-4=3,left=5→ends
- Final `min_len=2`. ✓ Matches expected output.

### Complexity

- **Time:** O(n) — each element is added once (`right` pointer) and removed at most once (`left` pointer), so total pointer movement is O(n).
- **Space:** O(1) — only a few scalar accumulators.

### Python Solution

```python
from typing import List


class Solution:
    def minSubArrayLen(self, target: int, nums: List[int]) -> int:
        left = 0
        window_sum = 0
        min_len = float('inf')

        for right in range(len(nums)):
            window_sum += nums[right]
            while window_sum >= target:
                min_len = min(min_len, right - left + 1)
                window_sum -= nums[left]
                left += 1

        return min_len if min_len != float('inf') else 0


if __name__ == "__main__":
    sol = Solution()
    print(sol.minSubArrayLen(7, [2, 3, 1, 2, 4, 3]))          # 2
    print(sol.minSubArrayLen(4, [1, 4, 4]))                    # 1
    print(sol.minSubArrayLen(11, [1, 1, 1, 1, 1, 1, 1, 1]))    # 0
```

## 6. Happy Number

**Difficulty:** Easy
**Link:** https://leetcode.com/problems/happy-number/

### Problem

A number `n` is "happy" if repeatedly replacing it with the sum of the squares of its digits eventually reaches `1`. If this process instead loops forever in a cycle that never includes `1`, `n` is not happy. Determine whether a given `n` is happy.

**Examples**
- `n = 19` → `true` (19 → 82 → 68 → 100 → 1)
- `n = 2` → `false`

**Constraints:** `1 <= n <= 2^31 - 1`.

### Intuition

This is a **cycle detection** problem in disguise: repeatedly applying the "sum of squared digits" function defines an implicit sequence, and it's a known fact that this sequence either reaches `1` or falls into one of a small number of repeating cycles — it never diverges to infinity (because the sum of squares of digits of any number is bounded well below the number itself once the number has more than 3 digits). So the question becomes: does this sequence hit `1`, or does it start repeating a value it has already seen?

Two standard ways to detect the cycle:
- **Hash set:** track every value seen; if a value repeats before hitting 1, it's a cycle → not happy.
- **Floyd's cycle detection (slow/fast pointers):** advance a "slow" pointer one step at a time and a "fast" pointer two steps at a time through the sequence; if they ever meet at a value other than 1, there's a cycle.

The hash-set approach is simpler to read and still efficient given the bounded cycle length, so we'll use that.

### Step-by-step walkthrough

1. Define a helper `next_value(x)` that computes the sum of squares of the digits of `x` (repeatedly extract digits via `%10` and `//10`).
2. Initialize an empty `seen` set.
3. Loop: while `n != 1` and `n not in seen`:
   - Add `n` to `seen`.
   - Set `n = next_value(n)`.
4. Return `n == 1` (loop exits either because we reached 1, or because we detected a repeat — a cycle not containing 1).

Trace with `n = 19`:
- seen={}, n=19 → add 19, n = 1²+9² = 1+81 = 82
- seen={19}, n=82 → add 82, n = 64+4 = 68
- seen={19,82}, n=68 → add 68, n = 36+64 = 100
- seen={19,82,68}, n=100 → add 100, n = 1+0+0 = 1
- Loop condition `n != 1` now false → exit. Return `n==1` → `True`. ✓

Trace with `n = 2`: sequence goes 2→4→16→37→58→89→145→42→20→4→... (4 repeats) → cycle detected without hitting 1 → `False`. ✓

### Complexity

- **Time:** O(log n) per digit-sum computation, and the sequence enters a bounded cycle (numbers stay under ~243 for any starting `n` with up to 7 digits) very quickly — effectively O(1) amortized iterations for the cycle-detection loop, so overall it's treated as O(log n).
- **Space:** O(log n) / O(1) amortized — the `seen` set stays small since the sequence collapses into a small range quickly.

### Python Solution

```python
class Solution:
    def isHappy(self, n: int) -> bool:
        def next_value(x: int) -> int:
            total = 0
            while x > 0:
                digit = x % 10
                total += digit * digit
                x //= 10
            return total

        seen = set()
        while n != 1 and n not in seen:
            seen.add(n)
            n = next_value(n)

        return n == 1


if __name__ == "__main__":
    sol = Solution()
    print(sol.isHappy(19))  # True
    print(sol.isHappy(2))   # False
```

## 7. Minimum Adjacent Swaps to Alternate Parity

**Difficulty:** Medium
**Link:** https://leetcode.com/problems/minimum-adjacent-swaps-to-alternate-parity/

### Problem

Given an array `nums` of **distinct** integers, you may swap adjacent elements any number of times. An arrangement is "valid" if every pair of neighboring elements has different parity (one even, one odd). Return the minimum number of adjacent swaps needed to reach some valid arrangement, or `-1` if it's impossible.

**Examples**
- `nums = [2,4,6,5,7]` → `3`
- `nums = [2,4,5,7]` → `1`
- `nums = [1,2,3]` → `0`
- `nums = [4,5,6,8]` → `-1`

**Constraints:** `1 <= nums.length <= 10^5`, `1 <= nums[i] <= 10^9`, all elements distinct.

### Intuition

First, feasibility: for a length-`n` array to alternate parity, the counts of even and odd numbers must differ by at most 1 (`abs(evenCnt - oddCnt) <= 1`). If they differ by more, no arrangement can alternate — return `-1` immediately.

Once feasible, notice a key fact about adjacent swaps: **the relative order of same-parity elements never needs to change**, and a classic result is that the minimum number of adjacent swaps to move a subset of elements into a specific set of target positions (while relative order among that subset is preserved) equals **the sum of absolute differences between each element's current index and its assigned target index**, when elements are matched to targets in order (i.e., the *k*-th even element goes to the *k*-th "even slot" of the target pattern). This is essentially the same insight used in "minimum swaps to group elements" style problems, and it also equals counting inversions of the assignment, but taking elements in order to target slots in order avoids any inversions in the first place, so the sum of `|position - target|` is the direct answer — no additional counting of crossings is needed as long as we consistently keep relative order.

There are at most two possible alternating patterns: starting with an even number at index 0, or starting with an odd number at index 0. Compute the swap cost for each feasible pattern and take the minimum. If `n` is odd, only the pattern whose starting parity matches the majority count is feasible (the majority must occupy the "extra" slot, e.g. index 0, 2, 4, ...). If `n` is even, both patterns are feasible (they simply swap which parity leads), so we try both and take the smaller cost.

### Step-by-step walkthrough

1. Split `nums` into two lists of original indices: `even_idx` (indices of even numbers, in original order) and `odd_idx` (indices of odd numbers, in original order). Let `evenCnt = len(even_idx)`, `oddCnt = len(odd_idx)`.
2. If `abs(evenCnt - oddCnt) > 1`, return `-1`.
3. Define a cost function `cost(idx_list, start)`: this pattern places elements of this parity at target positions `start, start+2, start+4, ...`. Sum `abs(idx_list[k] - (start + 2*k))` for each `k`.
4. Determine which starting patterns are feasible:
   - If `evenCnt == oddCnt` (n even): both "even starts at 0" and "odd starts at 0" are feasible. Compute `cost(even_idx, 0) + cost(odd_idx, 1)` and `cost(odd_idx, 0) + cost(even_idx, 1)`; take the minimum.
   - If `evenCnt > oddCnt` (n odd, evens are majority): only "even starts at 0" is feasible. Compute `cost(even_idx, 0) + cost(odd_idx, 1)`.
   - If `oddCnt > evenCnt`: only "odd starts at 0" is feasible. Compute `cost(odd_idx, 0) + cost(even_idx, 1)`.
5. Return the computed minimum cost.

Trace with `nums = [2,4,5,7]` (evens at indices [0,1], odds at indices [2,3]; evenCnt=2, oddCnt=2, so `n` even, both patterns tried):
- Pattern A (even leads, start=0): even targets = [0,2], odd targets=[1,3].
  - even cost: `|0-0| + |1-2| = 0+1 = 1`
  - odd cost: `|2-1| + |3-3| = 1+0 = 1`
  - total = 2
- Pattern B (odd leads, start=0): odd targets=[0,2], even targets=[1,3].
  - odd cost: `|2-0| + |3-2| = 2+1 = 3`
  - even cost: `|0-1| + |1-3| = 1+2 = 3`
  - total = 6
- Minimum = `min(2, 6) = 2`... 

Let's double check against expected output `1`. Re-examining: the expected answer for `[2,4,5,7]` is achieved by swapping 4 and 5 → `[2,5,4,7]`, one swap. Pattern A (even at 0,2 / odd at 1,3) exactly matches `[even,odd,even,odd]` = `[2,5,4,7]`, using indices: even numbers `2`(idx0),`4`(idx1) go to targets `0,2`; odd numbers `5`(idx2),`7`(idx3) go to targets `1,3`. Cost: even: `|0-0|+|1-2|=1`; odd: `|2-1|+|3-3|=1`; total=2 — but actual answer is 1 swap. This shows the simple sum-of-abs-difference must be **halved**: each adjacent swap moves *one* element by 1 position but simultaneously moves another element by 1 position in the opposite direction, so a single physical swap reduces the total displacement sum by 2, not 1. Dividing the total displacement by 2 gives the true swap count: `2 / 2 = 1`. ✓ That matches.

So step 3 must be corrected: the final answer for a pattern is `sum(abs(idx_list[k] - target)) // 2` combined appropriately — more precisely, compute the total absolute displacement across *both* parity groups combined, then divide by 2 (since swaps are shared between the two interleaved groups).

Corrected trace: Pattern A total raw displacement = `1 (even) + 1 (odd) = 2`; swaps = `2 // 2 = 1`. ✓
Pattern B total raw displacement = `3 + 3 = 6`; swaps = `6 // 2 = 3`.
Minimum = `min(1, 3) = 1`. ✓ Matches expected output.

Re-verify with `nums = [2,4,6,5,7]` (evens at idx [0,1,2], odds at idx [3,4]; evenCnt=3, oddCnt=2, n=5 odd, majority evens → only pattern "even leads" feasible, even targets=[0,2,4], odd targets=[1,3]):
- even raw cost: `|0-0|+|1-2|+|2-4| = 0+1+2 = 3`
- odd raw cost: `|3-1|+|4-3| = 2+1 = 3`
- total raw = 6; swaps = `6 // 2 = 3`. ✓ Matches expected output of `3`.

### Complexity

- **Time:** O(n) — a single pass to bucket indices by parity, then O(n) to compute displacement sums for at most two candidate patterns.
- **Space:** O(n) for the two index lists.

### Python Solution

```python
from typing import List


class Solution:
    def minSwaps(self, nums: List[int]) -> int:
        even_idx = [i for i, x in enumerate(nums) if x % 2 == 0]
        odd_idx = [i for i, x in enumerate(nums) if x % 2 == 1]
        even_cnt, odd_cnt = len(even_idx), len(odd_idx)

        if abs(even_cnt - odd_cnt) > 1:
            return -1

        def raw_cost(idx_list: List[int], start: int) -> int:
            return sum(abs(idx - (start + 2 * k)) for k, idx in enumerate(idx_list))

        candidates = []
        if even_cnt >= odd_cnt:
            # even-leads pattern: evens at 0,2,4,... ; odds at 1,3,5,...
            candidates.append(raw_cost(even_idx, 0) + raw_cost(odd_idx, 1))
        if odd_cnt >= even_cnt:
            # odd-leads pattern: odds at 0,2,4,... ; evens at 1,3,5,...
            candidates.append(raw_cost(odd_idx, 0) + raw_cost(even_idx, 1))

        return min(candidates) // 2


if __name__ == "__main__":
    sol = Solution()
    print(sol.minSwaps([2, 4, 6, 5, 7]))  # 3
    print(sol.minSwaps([2, 4, 5, 7]))     # 1
    print(sol.minSwaps([1, 2, 3]))        # 0
    print(sol.minSwaps([4, 5, 6, 8]))     # -1
```
